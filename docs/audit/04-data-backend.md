## Endpoint and rule contract summary

- **Map viewport:** none found. Pan/zoom filters already-loaded records against Leaflet bounds in `src/components/map/hooks/useMapPinsClustering.ts:1015-1026`; no network request is triggered by a settled viewport event in the reviewed render path.
- **Map browse/search:** no dedicated endpoint. Business suggestions are an in-memory top-five substring filter; directory search and filters are also in-memory over the global catalog.
- **Catalog endpoint:** `GET {SUPABASE_REST_BASE}/businesses` with a fixed `select`, `package_id != pkg_interested_lead`, `verification_status = verified`, stable `created_at desc,id asc`, `Range` pages of 60 then 500, `Prefer: count=exact`. Failure becomes a global directory warning, not a map-scoped state.
- **Pagination consistency:** one endpoint/query shape for all pages; exact total is read from `Content-Range`. If absent/unparseable, completion falls back to a short page or empty response. A short page is therefore treated as terminal. No cursor pagination or map result limit exists.
- **Sorting:** server order is catalog order, but parent `PublicShowcase` re-sorts the full client result according to active user sort/default shuffle before `MapView` receives it. `MapView` also receives sort props, but the reviewed `InteractiveMap` marker path applies its own ranking. Sort intent is not a single shared map/query contract.
- **Source of truth:** Supabase `businesses` is the persistence source; the browser catalog/cache is the current read model. Filter/search truth is split across shared client utilities and local suggestion/map logic, not enforced server-side.

## Requested performance / correctness checks

- **N+1:** no per-pin network fetch appears in the reviewed map render path; pins are built from the in-memory catalog. N+1 cannot be assessed inside database views/functions not present in the repository.
- **Indexes:** no schema/migrations/index definitions were reviewed or found in the project source search. Spatial/text index presence is unknown, not a confirmed omission.
- **Caching:** `dalelak_directory_cache` seeds startup data and is rewritten from the in-memory catalog; it strips `notes` and limits cached photos to one. Its age/version/expiry is not checked here. Offline startup can show that cached snapshot; the next REST refresh failure leaves it available and records a generic partial-data warning. No explicit offline map status or cache freshness indicator was found in the inspected wiring.
- **Debounce/cancel:** business text suggestions update from in-memory data without requests. Directory filtering uses `useDeferredValue` (`PublicShowcase.tsx:66-67`); map geocoding hook has its own debounce but its search mode is picker/geocoding, not the production browse suggestion contract (`docs/audit/01-map-inventory.md` §2/§7). Full catalog fetches are abortable when superseded; map pan/zoom does not issue a request to cancel.
- **Optimistic updates:** no optimistic map data mutation found. Realtime catalog updates are immediate and layered over refresh state.
- **Status/error/partial failure:** non-OK HTTP or non-array JSON fails the loader; a failed later page leaves partial data and a generic global error string. No structured retry affordance scoped to the map was confirmed. Actual HTTP response bodies/status distributions were not observed.
- **Duplicates/data quality:** no deduplication beyond entity ID map replacement in `mergeCatalog`; no coordinate/category duplicate audit was performed against live data. Invalid coordinates are excluded by the map helper; textual zone fallback is used only when coordinates are unusable for zone classification, while the map pin filter itself requires usable coordinates first.
